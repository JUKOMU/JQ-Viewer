# 10. 常见问题与反馈

遇到问题时，先记下当前页面、执行的操作和完整错误提示，再按本章找到相应入口。详细操作步骤仍以对应章节为准；排查结果也可以作为后续反馈的一部分。

同一作品可能同时出现在收藏、历史、下载任务和本地文件列表中。检查时先确认当前页面管理的是哪一类内容，尤其在删除、清空或重试前核对操作对象。

<a id="find-the-problem"></a>

## 10.1 先判断问题发生在哪一步

| 现象 | 先查看哪里 | 本章说明 |
| --- | --- | --- |
| 安装失败、桌面便携版无法启动 | 安装包平台、架构、包类型，是否完整解压 | [10.2](#installation-problems) |
| 应用内检查更新失败或停在安装前 | 设置 → 关于；更新状态和具体提示 | [10.2](#installation-problems) |
| 搜索、分类或作品详情无法加载 | 当前联网状态、API 线路 | [10.3](#network-and-images) |
| 详情有文字，但图片加载失败 | 图片线路、失败页的重试入口、当前阅读来源 | [10.3](#network-and-images) |
| 自动登录失败、收藏数量不符合预期 | 账号状态，在线／离线收藏来源和当前文件夹 | [10.4](#login-and-favorites) |
| 本地阅读入口不可用，或位置恢复不符合预期 | 选中的章节、文件关联及阅读入口 | [10.5](#reading-problems) |
| 下载、导出失败，或找不到输出文件 | 下载状态、导出任务、文件列表与实际保存位置 | [10.6](#files-and-tasks) |
| 文件显示缺失、无法读取或损坏 | 文件是否存在、目录权限、文件校验结果 | [10.6](#files-and-tasks) |
| 清理后仍有同名条目、提示或阅读位置 | 历史、搜索提示、缓存分别属于哪类数据 | [10.7](#history-and-cache) |
| 仍无法定位原因，需要反馈 | 错误发生时间、操作步骤和相关日志 | [10.8](#collect-evidence)、[10.9](#submit-feedback) |

一次先处理与当前现象直接相关的设置，保留操作前后的结果。这样既便于确认哪一步产生了变化，也方便在反馈中说明已经尝试过什么。

## 10.2 安装、启动与更新

### 下载到了文件，却不能安装

先核对下载的是发行包。Releases 中的 `Source code` 是源码压缩包，不能代替 APK、安装程序或桌面便携包。

再检查平台和架构：

- **Android**：最低支持 Android 7.0；不确定架构时，可以使用正式版提供的通用 APK。安装授权按设备显示的提示完成。
- **Windows**：使用 Windows x64 发行包；Windows on ARM 需要系统支持 x64 应用仿真。
- **Linux**：区分 x64 和 arm64，并按系统选择 DEB、RPM 或 TAR.GZ。

反馈安装失败时，保留完整安装包名称、系统版本，以及系统显示的错误文字。完整选包与安装步骤见[第 2 章《下载、安装与更新》](installation.md)。

### 桌面便携包解压后仍不能启动

确认已经完整解压，并保留应用目录结构：

- Windows 便携版从解压目录中的 `JQ-Viewer.exe` 启动。
- Linux TAR.GZ 从解压目录中的 `bin/JQ-Viewer` 启动。

不要只取出启动文件单独运行。正式桌面发行包包含 Java 运行时，正常使用不需要先搭建 JDK、Maven 或 Node.js 开发环境。

仍无法启动时，记录你运行的文件、启动方式、完整错误提示和发生时间。如果无法进入应用内日志页，可以先提供这些信息，不需要为了收集日志而反复重装。

### 检查更新失败，是否表示已经是最新版

“检查失败”和“已是最新”是不同结果。先查看“设置 → 关于”显示的当前版本和检查状态，再核对联网情况；需要手动查看发行情况时，从项目仓库进入 Releases。

更新已经开始时，按当前状态判断下一步：

| 状态或提示 | 可以先做什么 |
| --- | --- |
| 下载失败、校验失败 | 保留错误提示，确认当前联网情况及可用空间，再按页面提供的操作重试 |
| 未授予通知权限，更新未开始 | 按应用提示处理通知权限，再重新发起更新 |
| 准备安装、等待安装权限 | 按“安装更新”和当前系统提示继续；下载结束还需要完成安装 |
| 安装后版本仍不符合预期 | 在实际打开的应用中再次查看版本，并说明此次使用的安装包和安装过程 |

不同平台的安装方式和权限提示可能不同，详见[第 2 章](installation.md)，以及[第 9 章 9.12“关于、更新与桌面端诊断”](settings/about.md#about-and-diagnostics)。

## 10.3 搜索、作品信息与图片加载

### 搜索或分类加载不出内容

先看侧边栏的联网状态，必要时进入“设置 → 网络状态”：

1. 如果显示在线客户端正在初始化，等待初始化结果。
2. 如果显示当前网络不可用或在线客户端暂不可用，先处理该状态。
3. 在线能力可用后，查看 API 线路状态；按需要刷新探测、测量延迟或选择候选线路。
4. 返回原页面，再核对相同操作的结果。

反馈时区分“请求报错”和“请求成功但没有结果”。后一种情况还应检查关键词、分类、筛选及排序条件，避免把检索范围问题直接当成连接故障。

API 与图片线路的操作说明见[第 9 章 9.9“网络状态与线路选择”](settings/network.md#network-settings)；搜索与分类规则见[第 4 章《首页搜索与分类》](search-and-categories.md)。

### 解析后的作品不对，或图片 OCR 识别出错

核对原始输入、选择的解析模式和识别出的数字。需要时先编辑识别文本，再重新提交；一张图片中的所有数字不一定都属于目标作品 ID。

解析历史保存了提交的文本，记录存在并不代表解析成功；重新打开记录也会再次处理文本。有关单个解析、批量解析和 OCR 的完整步骤，见[第 4 章](search-and-categories.md)；复用历史文本见[第 8 章](history.md)。

### 详情标题能显示，图片却加载失败

API 和图片使用不同线路。作品文字信息可以取得时，仍需要检查“网络状态”页的图片线路。

先确认是单页、部分图片，还是整个章节失败。阅读器提供失败图片重试入口时，可以在处理连接问题后重试，并记录结果。

切换或测速前先看当前图片模式：自动模式下测量全部图片线路，可能直接应用优选结果；手动固定时则需要根据结果决定是否重新选择。具体规则见[第 9 章 9.9](settings/network.md#network-settings)。

如果正在读已下载图片、PDF 或 CBZ，先检查对应本地内容是否可读；单纯切换在线线路不能修复缺失的本地文件。

### 断网后为什么部分页面仍然打不开

离线收藏可以保留条目信息，浏览历史也可以保留访问记录；完整作品详情、评论和没有准备好的图片内容仍可能需要联网。

准备离线阅读时，确认所需章节已完成下载，或本地 PDF／CBZ 可以读取，再从“下载”页进入。离线阅读与来源选择见[第 5 章 5.5“选择阅读来源”](reading.md#reading-sources)，下载和文件管理见[第 7 章](downloads.md)。

## 10.4 登录与收藏

### 自动登录失败或账号状态需要重试

先检查联网状态，再通过侧边栏账号区域按提示重试；也可以到“设置 → 用户”查看状态或进入登录页。手动登录失败时，保留错误提示，并核对用户名、密码和当前连接。

“下次自动登录”控制后续启动时是否尝试自动登录，不能保证网络异常或账号状态变化后仍能成功。详细步骤见[第 9 章 9.10“用户与登录”](settings/user.md#user-and-login)。

反馈登录问题只需要说明状态、发生步骤和错误信息，不要提交密码、验证码、Cookie 或其他登录凭据。

### 登录或登出后，收藏看起来变了

先打开收藏夹列表，确认查看的是“在线收藏夹”还是“离线收藏夹”，以及选中的具体文件夹。

在线收藏属于当前账号；离线收藏保存在当前设备。登出后页面会切换到离线收藏模式，不代表在线收藏被清空。切换账号、来源或文件夹时，应在正确来源下核对内容。

在线夹复制到离线，是一次复制；后续修改不会自动双向同步。复制、同步到在线与账号操作的区别，见[第 6 章 6.6“复制收藏夹与同步到在线”](favorites.md#copy-folders)。

### “全部”的数量为什么与各文件夹相加不一致

离线“全部”按作品 ID 汇总去重。同一作品存在于多个离线夹时，汇总中只显示一次。

查找条目时还要核对当前关键词和筛选。需要移动或取消某条离线收藏时，进入它实际所在的具体文件夹；不要把“全部”当成一个独立所属夹。

收藏查找、分组和批量操作见[第 6 章](favorites.md)。

## 10.5 阅读来源、进度与设置

### 设备上有文件，详情页的 PDF／CBZ 来源仍不可用

详情页的来源对应当前选中章节。文件需要已登记、可读取，并关联到该章节；只把文件放进设备目录，不一定会满足这些条件。

先到“下载 → 导出 → 文件”检查文件记录和状态，再核对作品、章节关联。尚未登记的 PDF／CBZ 按[第 7 章 7.7“导入已有 PDF 或 CBZ”](downloads.md#import-files)处理。

从文件列表直接打开整份文件，与从作品详情打开关联章节是不同入口。完整说明见[第 5 章 5.5](reading.md#reading-sources)。

### 点击“开始阅读”后，打开的来源与预期不同

“开始阅读”会按当前可用来源优先选择：已完成下载的图片、CBZ、PDF，最后是网络图片。希望使用特定来源时，展开旁边的来源按钮手动选择。

图片阅读器本身也会优先尝试已下载图片，因此选择网络图片入口不代表强制重新从网络取回所有页面。

### 没有恢复到预期位置

先核对进入的是同一作品、同一章节，还是文件列表中的整份文件。

作品章节按章节保存阅读位置；从文件列表直接打开 PDF／CBZ，则按文件保存位置。整份文件页码与章节内页码可能不同。

浏览历史用于返回作品详情和章节，不是页码记录。清空历史也不会统一重置阅读位置。相关说明见[第 5 章 5.7“阅读进度与切换章节”](reading.md#reading-progress)，以及[第 8 章《历史》](history.md)。

反馈时说明阅读来源、进入路径、章节或文件、离开前的位置和再次打开后的实际位置，便于判断是否为同一组进度。

### 设置保存后没有立即变化，或某项无法操作

预加载并发数、下载并发数需要重启应用进程；只切换页面不会生效。预加载页数在下次阅读生效。

屏幕方向、亮度、音量键等能力还受平台限制。桌面端禁用的选项会说明原因；全屏和常亮是否可用，也要以当前运行环境显示的状态为准。

完整设置范围、两端差异及生效时机见[第 9 章 9.3、9.4](settings.md#reader-settings)。

## 10.6 下载、导出与本地文件

### 下载已经提交，为什么还不能离线阅读

到“下载”视图检查对应章节是否已完成。排队、暂停、校验中或部分图片失败，都不能当作该章节已完整准备好。

根据任务菜单提供的暂停、继续、重试等操作处理，再核对最终状态。反馈时记录状态和原始错误；下载中途停下时，还要说明最后执行的是暂停、取消还是删除。

这些操作对已下载文件的影响不同，步骤和范围见[第 7 章 7.2—7.3](downloads.md#download-tasks)。

### 导出失败、部分完成，或提示文件已存在

先进入“下载 → 导出 → 导出任务”，查看任务状态、错误原因及已完成的卷，再到“文件”列表或实际目录核对结果。

| 情况 | 处理时需要确认的内容 |
| --- | --- |
| 目录未选择或权限失效 | 在设置或导出面板重新选择有效目录；有默认路径文字不代表已取得授权 |
| 可用空间不足 | 检查目标位置空间，处理后再重试 |
| 文件已存在 | 核对完整路径和文件名，再决定是否覆盖 |
| 部分完成 | 查看哪些卷已经成功，哪些卷未完成；保留实际结果用于判断 |
| 准备重试整个任务 | 重试会从第一卷开始重新导出，并覆盖已有同名文件，不是只补上失败的卷 |

不要仅凭“任务已提交”或进度一度达到某个数值判断最终成功。任务、分卷和覆盖操作的详细说明见[第 7 章 7.4—7.5](downloads.md#export-files)。

### 导出完成后找不到文件，或名称与预期不同

先切换到“下载 → 导出 → 文件”，核对来源、格式和搜索条件；再查看任务使用的实际路径。

设置页的路径预览使用示例数据，新建任务会使用实际作品与选章信息。合并导出的章节范围、分卷页码后缀和路径字符处理，也会影响最终名称。

修改模板或基础目录不会自动移动、重命名已经导出的文件。文件列表和实际结果见[第 7 章](downloads.md)，模板规则见[第 9 章 9.6—9.8](settings.md#favorite-export-format)。

### 本地文件显示“缺失”“无法读取”或“损坏”

先查看文件卡片状态，并使用“校验”核对：

- **文件缺失**：检查原文件是否被移动或删除。
- **无法读取**：检查文件或目录访问是否仍有效；必要时重新通过目录选择器导入。
- **文件损坏**：核对原文件是否完整、格式和内容是否有效；根据来源重新取得或重新导出后再校验。
- **待校验**：先校验并查看结果，不能直接认定已经损坏。

校验是检查当前文件状态，不会自动补回丢失内容或修复损坏文件。处理后重新核对读取结果；PDF 阅读器提示权限失效或需要重新导入时，按提示重新选择有效来源。

应用直接阅读的本地文件包括 PDF、CBZ；不要将导出得到的 ZIP 一概当作可直接打开的 CBZ。

文件查看、校验和导入见[第 7 章 7.6—7.7](downloads.md#local-files)。

### 只想整理列表，怎样避免误删文件

| 你要处理的对象 | 需要分清的操作 |
| --- | --- |
| 本地文件列表 | “移除”只移出文件库记录；“删除实际文件”会删除该定位符当前指向的文件 |
| 已结束的导出任务 | 删除任务记录，最终文件保留 |
| 图片下载任务与章节 | 取消、删除或清空可能同时清理对应下载图片，按下载页说明核对 |
| 浏览／解析历史 | 删除相应历史记录，不同时删除下载和本地文件 |

文件如果被外部程序替换，同一个定位符可能指向替换后的文件；执行“删除实际文件”前，应核对确认框中的当前信息。具体删除范围见[第 7 章 7.8“移除、删除与清空的区别”](downloads.md#delete-and-remove)。

## 10.7 历史、搜索提示与缓存

### 清空历史后，为什么仍有搜索提示或阅读位置

浏览历史、解析历史、搜索框提示、阅读位置分别保存。清空当前历史标签，只处理那一类历史。

需要清理输入框提示时，到对应输入框的历史提示列表操作；阅读位置不由历史页统一重置。再次访问作品或提交解析文本后，也可能生成新的历史记录。

### 清空缓存后，下载文件为什么还在

缓存和下载文件分别管理。清空图片缓存会处理图片缓存和 PDF 页面缓存，保留下载图片与本地 PDF／CBZ；继续阅读时可能重新取得图片或生成页面缓存。

要管理实际文件占用，到下载页处理相关内容。不要用历史条数或缓存用量推断设备上全部文件的大小。

### 多选后为什么数量多于屏幕上可见的卡片

不同页面的全选范围有各自规则。历史页的全选覆盖当前标签全部记录，包括折叠分组和尚未加载的条目；其他列表应核对当前筛选、来源和该页面的范围说明。

批量删除前查看已选数量和确认框，不能将“当前屏幕可见条目”直接当作操作范围。历史整理见[第 8 章](history.md)，缓存说明见[第 9 章 9.2](settings/cache.md#image-cache)；收藏和下载的多选范围见各自章节。

## 10.8 收集错误信息与日志

### 先记下最小必要信息

| 信息 | 怎样写更容易定位 |
| --- | --- |
| 平台与系统 | Android／Windows／Linux，以及系统版本；Linux 同时注明发行版 |
| 设备与架构 | 设备型号、x64／arm64 等；安装问题补充完整安装包名和包类型 |
| 应用版本 | 从“设置 → 关于”取得；打不开应用时提供安装包文件名，并说明无法查看应用内版本 |
| 发生时间 | 尽量精确到分钟，并说明时区，便于与日志对应 |
| 复现步骤 | 从哪个页面进入、点击什么、使用何种输入或文件，按顺序列出 |
| 预期与实际结果 | 分别说明原本希望发生什么、实际发生什么 |
| 原始错误 | 保留完整文字；同时注明是页面提示、系统提示还是日志内容 |
| 发生范围 | 每次还是偶发；只影响某章节、文件或任务，还是多个对象 |
| 已尝试操作 | 记录操作及其结果，例如换图片线路后仍失败，而不是只写“都试过了” |

涉及账号时，说明登录状态即可；涉及本地文件时，优先提供格式、来源、页数、状态和必要的关联信息。确实与复现有关的作品／章节 ID 可以单独提供，避免附上整个收藏或历史列表。

### 导出对应时间的日志

1. 进入“设置 → 诊断 → 应用日志”。
2. 记录日志文件名和相关错误；需要文件时点击“导出日志”。
3. 选择覆盖问题发生时间的日志文件，导出到你选择的目录。
4. 核对导出结果和实际文件，再选择要附到反馈中的内容。

当前页面最多保留最近 500 行，不能只凭界面中没看到更早内容就判断不存在相关日志。导出面板可以选择日志文件，完整步骤见[第 9 章 9.11](settings/logs.md#application-logs)。

网络状态页底部的“事件日志”只用于线路过程，不能代替独立的应用日志。桌面端还可以从“关于 → Desktop 诊断”补充相关任务状态和错误摘要，见[第 9 章 9.12](settings/about.md#about-and-diagnostics)。

应用完全打不开、日志页读取失败或日志导出失败时，直接说明无法提供的原因，并保留该错误本身。仍可先提供版本、系统、时间、步骤和启动错误。

### 分享前查看内容

检查准备公开的日志、图片和文字，保留与问题相关的上下文，处理无关账号信息、私人目录和其他敏感内容。

不要附上密码、验证码、Cookie、访问令牌或完整应用数据库。文件问题可以先提供状态与必要元数据，不必直接公开漫画文件或整个下载目录。需要对照路径时，可以一致地替换私人目录部分，并注明已脱敏。

例如，两处相同的私人父目录都替换成 `<个人目录>`，保留文件名、目录层级和错误位置；不应将不同文件都替换成同一个名称，以免丢掉问题线索。

导出日志只保存到选定目录，不会自动上传。公开反馈中附哪些内容，由你在提交前决定。

## 10.9 提交和补充问题反馈

### 从哪里反馈

可以从“设置 → 关于”中的 Issue 指引进入 JQ Viewer 仓库，也可以直接进入该仓库的 Issues。

先搜索相似现象和关键错误文字。如果已有同一问题，可以在原讨论中补充你的平台、版本和复现结果；不同问题分别描述，方便后续确认与修复。

新建反馈时，按 GitHub 网页当前提供的表单填写。下面的内容用于准备信息，不要求在线表单必须出现完全相同的字段。

### 功能建议怎样说明

说明你在哪个页面、准备完成什么任务、现有流程具体卡在哪里，以及希望得到什么结果。如果涉及 Android 和桌面端，说明两端需求是否相同。

优先描述使用场景；可以附上你想到的操作方式，但不需要先设计完整实现方案。

### 提交之后

保留原反馈，后续的新日志、补充步骤或版本验证结果继续补在同一讨论中。验证新版本时，注明测试的平台、版本和原问题是否仍能复现，不只写“好了”或“还是不行”。

问题暂时没有明确结论时，区分已经观察到的现象和自己的原因推测；这能避免后续排查围绕未经确认的假设反复进行。
